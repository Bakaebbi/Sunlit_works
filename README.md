# Sunlit Works - веб-разработка

Статическое портфолио на HTML, CSS, Vanilla JavaScript и GSAP. Vite собирает главную и страницы кейсов. Позиционирование остаётся веб-разработкой.

## Запуск и проверка

```powershell
npm ci
npm run dev
```

Перед запуском автоматически выполняется `prepare:site`: подготавливает WebP, навигацию, статические карточки и метаданные.

```powershell
npm run build
npm run check
npm run preview
```

`build` подготавливает материалы и создаёт `dist/`. `check` проверяет готовую сборку: количество статических карточек и ссылок, размеры обложек, идентификаторы переходов и наличие локальных ресурсов. Для публикации нужен только `dist/`. Подпапка хостинга поддерживается относительными путями.

## Добавление проекта

1. Сохранить исходную обложку и реальные скриншоты в `assets/projects/`.
2. Создать страницу кейса в `projects/` (можно использовать существующую как основу), сохранив классы `case-switcher`, `case-visual cover` и `case-story`.
3. Добавить объект в `data/projects.json` с уникальным `id` из латинских букв, цифр и дефисов. Имя `main` зарезервировано.

```json
{
  "id": "new-project",
  "title": "Название проекта",
  "description": "Короткое описание",
  "category": "Сайты",
  "technologies": ["HTML", "CSS"],
  "caseUrl": "projects/new-project.html",
  "siteUrl": "https://example.com/",
  "coverSource": "assets/projects/new-project.png",
  "previewSource": "assets/projects/cases/new-project-screen.png",
  "mediaSources": ["assets/projects/cases/new-project-detail.png"]
}
```

Для обложки в общем стиле можно дополнительно задать `artwork`: `screen` (путь к реальному скриншоту), `background` и `ink` (цвета). Без `artwork` используется `coverSource`. Исходники сохраняются; готовые квадратные обложки создаются в размерах 160/480/960 px. `mediaSources` перечисляет изображения внутри кейса, которые надо оптимизировать. Их исходные пути в `<img>` заменяются подготовленными WebP.

4. Выполнить `npm run prepare:site` или перезапустить `npm run dev`. Скрипт обновит все переключатели кейсов, главную и встроенные данные. Vite автоматически включит новую страницу в сборку. Новая категория автоматически создаст ветку карты; переход получит идентификатор из `id`.
5. Проверить `npm run build`, `npm run check` и интерфейс на компьютере и телефоне.

Поля `cover`, `coverSources`, `thumbnail`, `preview`, размеры и подписи обложек вычисляются автоматически. `public/` содержит подготовленные материалы; редактировать нужно исходники и JSON. Генерируемую область карточек в `index.html` и навигацию кейсов также обновляет скрипт. Редакционные тексты кейсов остаются в HTML. Из поля `siteUrl` автоматически создаётся компактная ссылка «Открыть сайт» в закреплённой шапке каждого кейса; она открывает проект в новой вкладке с сохранением страницы портфолио.

## Представления и возврат

- «Галерея»: равные квадратные обложки, на телефоне горизонтальная лента.
- «Проекты»: компактный список.
- «Карта»: категории и проекты со связями SVG, перетаскиванием, масштабированием и сворачиванием веток.

`browse-state.js` хранит состояние на время вкладки. После закрытия кейса возвращаются выбранный проект и фокус, позиция галереи/списка, масштаб и положение карты, свёрнутые категории. Переключение между кейсами обновляет выбранный проект для возврата.

На узких экранах карта начинает с читаемого масштаба. Кнопки с названиями приближают конкретную работу; «Вписать» показывает обзор. Работают мышь, колесо, перетаскивание пальцем и жест двумя пальцами. При фокусе на полотне стрелки перемещают карту, +/− меняют масштаб, Home вписывает её.

## Анимация и доступность

`project-motion.js` управляет наведением и анимированными снимками реальных сайтов. `page-motion.js` - движением галереи и появлением содержимого кейсов. `project-transition.css` - переходами между представлениями и страницами. Идентификаторы изображений формируются из `id`, без отдельного списка проектов в CSS. `prefers-reduced-motion` отключает декоративное движение. Карточки и навигация работают без JavaScript; интерактивность улучшает статическую страницу.

## Главная и «Обо мне»

Название портфолио - Sunlit Works. Нажатие на название в шапке возвращает в галерею и сбрасывает её прокрутку. Ссылка также содержит `?view=gallery` для обычного открытия в новой вкладке. Sunlit Tile остаётся названием игровой студии в тексте «Обо мне»; адрес почты не менялся.

Слева от «Контакты» находится «Обо мне». `about.js` открывает нативный модальный диалог: размытый фон, узкая колонка текста и мягкое появление разделов. Поддерживаются Escape, крестик, нажатие снаружи, блокировка фоновой прокрутки и возврат фокуса. Название внутри диалога закрывает его и возвращает галерею. `prefers-reduced-motion` делает открытие и закрытие мгновенными. Текст внутри `#about-dialog` в index.html - согласованный текст; генератор его не перезаписывает.

## Контакт

В шапке - кнопка «Связаться» с адресом sunlit.tile@gmail.com. При наведении или фокусе появляется плашка с почтой; нажатие копирует адрес с подтверждением. Нажатие на сам адрес открывает письмо через mailto. Если браузер запрещает копирование, об этом сообщается, а ссылка остаётся доступной. Escape и нажатие вне плашки закрывают её. Без JavaScript основной контакт сразу работает как mailto-ссылка. Ссылки на FL.ru в интерфейсе нет.

Для карты генератор отдельно создаёт широкие версии обложек в размерах 330×220 и 660×440. Поэтому прямоугольные узлы заполнены без белых боковых полей; в галерее и кейсах сохраняются квадратные версии. Источники автоматически переключаются при смене режима.

## Звук

Общий модуль `sounds.js`: тихие синусоидальные отклики для наведения, открытия, закрытия и переключения. Общая палитра охватывает режимы просмотра, кнопки галереи, ветки и фокус проектов на карте, масштабирование кнопками/клавишами, сброс вида, подтверждение копирования почты и внешние ссылки. Автоматические перестроения карты и непрерывные жесты не запускают отклики. Включение звука подтверждается тихим тоном, выключение останавливает воспроизведение. Открытие повышает тон, закрытие понижает. Выбор выключения сохраняется в sessionStorage. Браузер может разрешить воспроизведение только после первого пользовательского жеста. Обычный переход кратко отложен для завершения звука; модифицированные нажатия сохраняют поведение ссылок.

## Подготовка к публикации

Уже добавлены favicon, заголовки Sunlit Works, описание, Open Graph и изображение 1200×630. Когда известен конечный адрес, задайте `SITE_URL` перед сборкой - с подпапкой, если она есть:

```powershell
$env:SITE_URL = 'https://your-domain.example/portfolio/'
npm run build
Remove-Item Env:SITE_URL
```

Тогда сборка создаёт абсолютные OG/canonical URL и sitemap.xml; robots.txt ссылается на карту сайта. Без адреса используются локальные превью, canonical не выдумывается.

## Пунктуация

В авторском тексте используются только короткие дефисы U+002D. `npm run check:punctuation` проверяет исходники и документацию; `npm run check` дополнительно проверяет готовые HTML-файлы.

## Публикация на GitHub Pages

Репозиторий: `Sunlit_works`. Исходники хранятся в `main`, готовый сайт публикуется из корня ветки `gh-pages`. В Settings > Pages выбран источник Deploy from a branch, ветка `gh-pages`, каталог `/ (root)`.

Адрес сайта: `https://bakaebbi.github.io/Sunlit_works/`. Перед сборкой задайте `SITE_URL=https://bakaebbi.github.io/Sunlit_works/`, затем выполните `npm run build` и `npm run check`. Содержимое `dist` вместе с пустым файлом `.nojekyll` нужно закоммитить и отправить в `gh-pages`. Push только в `main` сохраняет исходники, но не обновляет опубликованную сборку. Свой домен не требуется.
